# 项目类型配置

只读取与当前项目相关的一节。项目类型配置只补充证据和专项检查，不改变主流程、P0 规则或用户终审权。没有匹配类型时使用 `general`。

## general

- 核心要求能够通过文件、运行结果或用户确认检查。
- 每条关键需求绑定当前版本证据。
- 无法验证的条件明确标为 `unverifiable`。

## code

- 证据：构建日志、测试输出、关键运行路径。
- P0：构建成功、核心路径可运行、无阻断性错误。
- 安全：不保存密钥，不执行用户未授权的破坏性操作。

## web

- 证据：页面截图、交互记录、控制台状态。
- P0：页面可打开、核心交互有效、无阻断错误。
- 检查：关键视口、溢出、无法访问的链接。

## document

- 证据：文件内容、结构检查、引用和渲染结果。
- P0：核心章节完整、事实和引用可追溯。
- 检查：受众、语气、链接、交叉引用。

## data-report

- 证据：字段说明、公式、重算结果、异常值检查。
- P0：数据口径明确、关键指标可复现。
- 检查：单位、缺失值、重复值、时间范围。

## design

- 证据：视觉截图、尺寸规格、实际使用环境。
- P0：符合用户给定的尺寸、用途和禁止项。
- 检查：层级、可读性、响应式表现。

## game

- 证据：启动记录、操作测试、胜负或完成流程截图。
- P0：能启动、核心操作有效、不会进入无法继续的状态。
- 检查：反馈、难度、重试、性能和完整流程。

## music

- 证据：可播放文件、时长、格式、响度和试听记录。
- P0：文件可播放，满足时长、格式和用途要求。
- 检查：结构、风格、情绪、素材授权和用户听感。

## safe-humor

- 适用于整蛊、互动幽默或恶作剧设计。
- P0：不得欺骗身份、索取敏感信息、造成财务或人身损害。
- 必须安全、可恢复、边界清楚；现实使用需要知情或明确同意。
- 优先用于游戏、虚构或双方明确同意的互动场景。
